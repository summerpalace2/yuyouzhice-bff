# 渝游智策 Android 端需求分析

> 状态：Android 开工基线（需求冻结前）  
> 适用范围：旅行者移动端；管理控制台不进入第一期原生端  
> 业务权威：Java Core Backend（`/ai/*`）

## 1. 产品目标与边界

Android 端不是 Web 页面的简单缩放版，而是同一账户、同一行程 ID、同一旅行记忆规则下的原生旅行规划客户端。第一期以手机竖屏为主，在平板上将行程、地图和对话扩展为自适应双栏/多栏布局。

必须还原的核心体验：游客问答、账号登录/注册/退出、自然语言 AI 规划、景点选择与多选、局部调整预览并确认、保存/恢复正式行程、景点探索、行程历史、旅行记忆、反馈来信、PDF 导出和地图路线展示。

第一期明确不做：管理员控制中心、知识库上传维护、Rerank 控制台、数字人、ASR/TTS、离线 AI 规划、主动推送。管理员仍使用 Web 控制中心；避免把治理功能塞进旅行者 App。

## 2. 不可违反的业务规则

### 2.1 身份与能力

| 身份 | 可做 | 不可做 |
| --- | --- | --- |
| 游客 | 独立游客 ID 下的旅行问答、查看公开景点信息 | AI 总规划、保存行程、局部调整、旅行记忆、历史与 PDF |
| 登录旅行者 | 完整规划、保存、恢复、局部调整、记忆、反馈、PDF | 无管理权限 |
| 管理员 | Android 第一阶段按旅行者能力使用 | 管理控制中心功能仍在 Web |

账号登录仅支持“邮箱/账号 + 密码”；注册成功后自动取得 Java JWT。退出后清除本机令牌与账户私有缓存，不清除游客聊天。

### 2.2 ID 与上下文隔离

| 数据域 | Android 本地键 / 服务端 ID | 影响范围 | 禁止事项 |
| --- | --- | --- | --- |
| 游客聊天 | `guestChatId`（本机生成并持久化） | 仅该游客对话 | 不得写账号、正式偏好或行程 |
| 规划草稿 | `plannerSessionId` + `sessionAccessToken` | 当前方案与当前调整对话 | 不得复用到另一份行程 |
| 正式行程 | `tripId` + `currentVersion` | 一份已保存行程 | 不得用本地对象替代版本校验 |
| 长期旅行记忆 | `userId` 下的确认记忆 | 后续新规划的可选辅助 | 不得覆盖本次行程条件 |

合并优先级固定为：

`本次明确输入 > 当前行程约束与已确认调整 > 当前行程摘要 > 用户确认的长期偏好 > 已确认旅行记忆 > AI 推断候选`。

任何低优先级内容与本次输入冲突时，客户端要展示本次输入为准，不能把旧聊天、旧行程或模型推断带入当前方案。

## 3. 第一期开关与页面范围

### 3.1 导航树

```text
启动
├─ 游客聊天（默认未登录入口）
│  ├─ 登录 / 注册
│  └─ 景点详情
└─ 已登录主框架
   ├─ AI 规划首页
   │  └─ 规划工作区（方案 / 地图 / 对话 / 局部调整预览）
   ├─ 探索重庆
   │  └─ 景点详情
   ├─ 我的行程
   │  └─ 已保存行程工作区 / PDF
   ├─ 历史会话
   └─ 旅行档案与记忆
      ├─ 已确认记忆
      ├─ 待确认候选
      └─ 反馈来信
```

### 3.2 页面需求与验收

| 页面 | 必须能力 | 验收关键点 |
| --- | --- | --- |
| 游客聊天 | 问答、单景点选中后“咨询详细信息”、去登录 | 使用独立 `guestChatId`；没有“保存/规划”入口 |
| 登录/注册 | 账号密码、错误提示、返回游客体验、退出 | 登录成功后恢复登录前草稿；不保存密码明文 |
| AI 规划首页 | 自然语言输入、常用规划、条件胶囊、启用记忆开关说明 | 当前输入永远可覆盖记忆；不自动保存方案 |
| 规划工作区 | 每日行程、地图、景点多选、聊天/局部调整、预览/确认应用、天气状态 | 任何调整先预览后应用；更新后使用服务端返回的新版本 |
| 景点详情 | 图片/标签/事实状态/到这去/加入行程 | 动态事实要有“已核验/待确认”状态；导航 URI 不携带服务端密钥 |
| 我的行程 | 列表、打开、删除、版本、导出 PDF | 只读取当前用户行程；PDF 文件名用行程标题 |
| 历史会话 | 展示和恢复用户自己的会话 | 恢复后绑定原 `tripId` 或新草稿 ID，不污染其他行程 |
| 旅行档案 | 旅行记忆开关、增改删、确认/忽略候选、来源与更新时间 | 当前方案不会被静默重写；候选不能自动生效 |
| 反馈来信 | 自由书写、快捷主题填充草稿 | 仅提交用户确认的文本；不把来信直接转为记忆 |

## 4. 交互和状态要求

1. 所有 AI、天气、局部调整请求均有加载、可恢复失败和重试态；面向用户的文案不能暴露“后端没有返回完整内容”。
2. SSE 聊天断开时保留用户输入和已完成片段，显示“暂时无法回答/可重试”，不能把内部异常当答案。
3. 景点“固定”表示在下一次局部调整中尽量不替换；它是当前行程状态，不是长期偏好。
4. 删除正式行程需要确认；管理员停用账号不属于 Android 第一阶段。
5. 手机端聊天以底部抽屉/全屏页面呈现；平板可与行程列表并列。地图全屏、反馈与确认弹窗必须盖住地图 SDK 控件。
6. 系统回收后至少恢复：当前路由、草稿输入、当前行程 ID、已选景点 ID、聊天滚动定位和未提交反馈草稿；令牌和完整聊天正文不能写入 `SavedStateHandle`。

## 5. API 与后端契约

Android 直接调用 Java Core 的 `/ai/*`，使用 `Authorization: Bearer <JWT>`；不调用 Web BFF 的 `/api/*`，也不依赖 Cookie、CSRF 或 Node 本地状态。

已可作为 Android 直连基础的 Java 域：`/ai/auth`、`/ai/attractions`、`/ai/chat/stream`、`/ai/planner/v1`、`/ai/trips`、`/ai/preferences`、`/ai/memories`、`/ai/history`。

### Android 开工前必须补齐的 Java 契约

| 缺口 | 现状 | 必须补齐的契约 |
| --- | --- | --- |
| 旅行档案聚合 | Web BFF 的 `/api/profile` 聚合了偏好、记忆、行程和反馈 | `GET /ai/profile`：返回当前用户档案、旅行记忆、候选、记忆开关、行程摘要和反馈摘要 |
| 旅行记忆开关 | 当前由 BFF 写入 `legacyMetadata` | `PUT /ai/profile/memory-settings`：`{ enabled }`，返回最终状态与更新时间 |
| 反馈来信 | 当前由 BFF 持久化，Android 直连不可用 | `POST /ai/feedback`、`GET /ai/feedback`，由 Java 数据库持久化并按用户隔离 |
| 行程工作区聊天 | Web 有额外 workspace 组装 | 明确 Java Planner 会话的对话读取/恢复契约，或新增 `GET/PUT /ai/planner/v1/sessions/{id}/workspace` |
| API 文档 | 没有可生成 Android DTO 的 OpenAPI 合约 | 发布版本化 OpenAPI 3.1 JSON；所有错误返回统一包含 `code`、`message`、`recoverable`、`traceId` |

这些接口补齐前，Android 只能完成游客聊天、登录、规划草稿、保存行程等子集，不能声称与 Web 完整等价。

## 6. 非功能需求

- **安全**：生产只允许 HTTPS；JWT 放 Android Keystore 加密存储；日志不得记录密码、JWT、`sessionAccessToken`、完整聊天或个人记忆。
- **网络**：所有请求都有连接/读取超时、取消、错误映射和幂等键；切换账号或离开会话时取消对应 SSE 与请求。
- **离线**：只缓存最近浏览过的景点、正式行程只读快照和未提交草稿；离线不能伪造 AI、天气或路线结果。
- **可访问性**：所有图标有语义标签，触控目标至少 48dp，动态状态用文本而非单色表达，中文字号支持系统字体缩放。
- **性能**：首次进入首页不初始化地图；仅规划工作区创建地图；离开时清理 marker/polyline 和监听器；大列表采用 `LazyColumn` 的稳定 key。

## 7. 第一阶段完成标准

1. 登录账号在 Web 和 Android 两端看到相同的正式行程、旅行记忆和版本号。
2. 同一账号的两份行程分别调整，聊天、选中景点、固定状态和草稿都严格隔离。
3. 游客可续聊但不能规划；登录后新规划可选择性召回已启用的旅行记忆。
4. 网络失败、AI 超时、天气未返回、版本冲突均有中文可恢复提示。
5. Android 主链截图与 Web 设计 token（暖白背景、砖红主色、卡片层级、中文信息密度）对齐，并完成手机与平板断点验收。
